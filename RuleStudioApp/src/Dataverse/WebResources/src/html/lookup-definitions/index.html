What is a lookup definition?A saved "find a value in another table" that rules use while they run, like VLOOKUP in Excel: find the row in table X that matches this record, and return column Y. Business data such as discounts, prices or approval limits stays in a table people can maintain, not inside the rules.

Example. A Discount table has the rows Partner · Nordic · 15, Partner · (empty) · 10 and (empty) · (empty) · 0. The lookup "Discount for quote" matches the quote's customer type and region and returns Discount %. A rule says set field Discount to the lookup "Discount for quote".

Values are read live. Each time a rule runs, the row is fetched from Dataverse. Change a row in the table and the next save uses it, with no need to publish the rules again.

If no row matches

  • Block: the save stops with an error.
  • Use default: a value you choose is used, for example 0.
  • Skip: the action is not carried out.

If several rows match

  • Most specific: an empty cell in a criterion column matches anything, and the row with the fewest empty cells wins. In the example a Nordic partner gets 15, other partners 10 and everyone else 0.
  • First by sort: the first row by the sort column, for example the newest price list.
  • Error: more than one match is a data error and the rule fails.

Where to use it. As the value in a Set field action, as the compared value in a condition, or as an input to a custom function. Define it once and reuse it in any number of rules. A lookup that is in use cannot be deleted, and Test lookup tries it on a real record without saving anything.

Lookup or field path? A field path follows a relationship the record already has, like the quote's account's credit limit. A lookup finds a row by matching values, with no relationship needed.
